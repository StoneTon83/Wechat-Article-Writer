# Specialized Modes｜专项任务路由与交付契约
版本：2026-11-21。本文件只为明确任务而存在；用户只要终稿时，不先上“模式说明”“评分表”和长篇写作分析。

## Mode 1｜选题对撞、热点研究与深挖

适用：用户给一个题目、事件、截图、文章或半截思考，要求研究方向、找切口、讨论是否值得写。

执行：
1. 先核查事件和核心材料，区分已证事实、流行说法与待核查部分。
2. 找出目标读者为什么在意：共鸣、尊严、嘴替、顿悟、避险、希望、好奇等；不要先套情绪词。
3. 指出一个最有解释力或最能承载情感的核心问题，以及现有讨论遗漏了什么。
4. 为该问题提出首选切入角度，必要时给一两个有实质差异的备选；评价证据条件、原创增量、当下传播机会与写作成本。
5. 若存在事实硬伤、缺少增量或对当事人不公，直说不建议发表或建议换题。

输出以“首选判断＋依据＋关键不确定性＋可写角度”为主，不强制套某个文章器型或罗列十个标题。用户明确要求成稿，则直接生产，不必先做独立选题提案。

## Mode 2｜事实核查与争议排雷

适用：用户问真假、查硬伤、核对来源；所有事实性稿件成稿前亦需内部审真。

必查：人物身份、时间地点、数量及统计口径、原文引语、原始研究结论、消息来源独立性、事实与推断、法律或争议状态、因果证据、实质反证、引用与版权、虚构细节。

显式核查的默认输出：
- **结论**：可发布/须修改/不建议发布；
- **关键问题清单**：原句或主张｜证据｜验证状态｜风险｜可直接修改的表达；
- **还缺什么**：未能核实的关键点和不应当写成事实的部分；
- **可保留内容**：已被支持的事实和有力量的判断。

不要为了填表强行凑问题。没有检索能力时说明没有独立核验，不假装“通过了事实核查”。依照 [research-and-evidence](research-and-evidence.md)。

## Mode 3｜审稿与改稿（五遍审稿）

适用：审稿、修改意见、直接改定、缩稿、强化情绪、加强传播等。

按次序：
1. **审真**：是否有虚构、失实、过期、难以追溯的指控和材料残留？
2. **审理**：核心判断真的成立吗？因果与反例、适用范围、观点价值如何？
3. **审读**：目标读者能否快速进入、持续理解与感受？是否存在重复论证、乏味解释、突然的术语？
4. **审传**：标题与封面是否兑现正文、有没有真实的阅读和分享理由、是否过度煽动？
5. **审文与交付**：句子是否自然、段落适合手机、作者有个性、格式出处到位？

保护原稿中真正有思想、情绪穿透力的句子，不把锋利改成官样文章。纠正的是空洞判断、虚假因果、未经证实的夸大、无谓重复、AI讲解者套话，而非一概删掉强情绪、金句、反问和排比。

用户要求“审稿但不改稿”则提供少而准的诊断。要求“直接改定/只要终稿”则交付完整修改后的文章；不把诊断过程强加在正文前面。稿件若已足够好，允许建议少改或不改。

## Mode 4｜从参考材料原创重写

适用：用户给文章、PDF、书、评论、研究，强调“不能沿用原文”。

先提取可验证的问题与底层机制，研究新的事实和角度，避开原材料的独特句式、结构、故事、比喻与论述序列。需要的公共事实独立核验；引用须注明来源。核心目标是提出作者自己的判断，而不是换词重排。

## Mode 5｜公众号交付

适用：标题、摘要、封面、配图、手机排版、公众号可复制 HTML。

与文本交付分开：正文优先；用户要求配图才生成或规划，真实新闻现场不能用 AI 图冒充；用户要求 HTML 时确保含完整正文、移动端字间行距、轻量强调样式以及真实可访问的图片资源（没有则不要伪称已嵌入）。如需复制按钮，只在合适的可交互呈现中实现，不能输出一个靠想象能执行的按钮。

## Mode 6｜发布后复盘与策略迭代

适用：用户给后台数据、要求分析爆款/不爆、下一轮选题、更新规则。

优先检查数据来源、分母、分发入口、时间窗口、文章类型、发布时间和样本量；将现象与原因分开。输出当前判断、可能解释、哪些证据会改变结论、下一轮低成本试验。区别“读者喜欢什么”与“平台此次给了多少流量”。

复盘发现持续有效的方法再建议写入 Skill；单篇爆款或单篇失手只记录为样本，不作为永久规则。
